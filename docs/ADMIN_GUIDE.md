# 管理者向けの手順

## 1. 入れる

1. 公式の「MCP Adapter」（WordPress.org）と、このプラグインを入れて有効にする。**このプラグインを先に有効にする**と、公式の既定サーバーができない（既定サーバーは、公開の印の付いたほかの Ability を出すことがある）。
2. 「設定 → Ship Content MCP → 診断」で、問題（赤）がないか確かめる。各項目に「対処」が出る。
3. REST を止めるコード（セキュリティの Snippet など）があるサイトでは、MCP の入口 `ship-content/` を通すようにする（ほかの REST は止めたままでよい）。

## 2. 使う投稿タイプと状態

| 状態 | できること |
|---|---|
| 未検証 | 読み取りだけ（入力欄の構造・制作方針・記事） |
| 試験中 | 下書きの作成・修正を試す。作った下書き・写真に試験の印が付き、`wp ship-content-mcp cleanup-tests --yes` で片付けられる |
| 試験合格・稼働 | 下書きの作成・修正ができる。**このときの入力欄の構造を記録し、その後に構造が変わったら、AI と「診断」に知らせる**（書き込みは止めない。基本設定の「入力欄が変わったら書き込みを止める」を入にすると、確かめ直すまで止める：ACF-003） |

- 最初は1つ（例：施工事例）だけを使う。ほかの投稿タイプは、既存の記事・入力欄・表示を確かめてから、未検証 → 試験中 → 試験合格の順に進める。
- ACF の入力欄を変えたら、「診断」の「確かめた構造」が黄色（止める設定なら赤）になり、AI の保存の返事にも知らせが入る。AI で試し、表示を確かめてから、基本設定の「いまの構造を確かめ直した」にチェックを入れて保存する。
- 固定ページ・メディア・内部の投稿タイプは、設定にかかわらず使えない。

## 3. 招待コードを発行して指示者に渡す（ブラウザで許可する接続・おすすめ）

1. 「設定 → Ship Content MCP → 接続」の「招待コードを発行する」で、ユーザー（ふつうは MCP 用のユーザー）・指示者の名前・入口の URL（https があれば https）を入れて発行する。
2. 出てきた2つを指示者に送る：**① AI に貼る文**（秘密なし。指示者は自分の AI に貼る）と、**② 招待コード**（指示者はブラウザの「接続の許可」の画面に入れる。AI には貼らない）。招待コードはこの1回だけ表示される。
3. 指示者の AI がブラウザを開き、指示者が招待コードを入れて「許可する」を押すと、一覧に「ブラウザで許可した接続」（AI の名前・期限）として出る。止めるときは「止める」。

- 招待コードは1回だけ・初期 7日。許可した接続の期限は、招待コードを発行するときに選ぶ（1週間・1か月・3か月・6か月・1年・無期限。初期 90日で、基本設定で変えられる。無期限は「止める」か公開前の片付けまで使える。WP-CLI は `--grant-days=<日>` か `--grant-days=unlimited`。切れたら新しい招待コードで許可し直す）。指示者1人のパソコン1台ごとに1つ発行する。
- 戻り先が https の AI（Claude の Web 版・デスクトップのコネクタなど、AI の会社のサーバーからつなぐもの）は、基本設定の「Web 版の AI からの接続も許す」をオンにしたときだけ。
- WP-CLI でも発行できる：`wp ship-content-mcp keys invite --for-user=<ID か new> --label='山田' [--entry-url=https://…/wp-json/ship-content/mcp]`。
- WordPress がドメインの直下にあること（`/.well-known/` をこのプラグインが返すため）。

### サーバーの Basic 認証があるサイト（公開前）

AI は Basic 認証を付けて OAuth の手続きをできないので、AI が自動で呼ぶ道だけを Basic 認証の例外にする。サイトのページと「接続の許可」の画面は Basic 認証のまま（指示者のブラウザが ID とパスワードを聞く）。例外にした道も、トークンがなければ何もできない。`.htaccess` の Basic 認証の部分を次の形にする（変更前の控えを取る）：

```apache
SetEnvIf Request_URI "^/wp-json/ship-content/(mcp|oauth/(register|token|revoke)|upload/[a-f0-9]{48})/?$" SHIP_MCP_OPEN
SetEnvIf Request_URI "^/\.well-known/(oauth-protected-resource|oauth-authorization-server|openid-configuration)" SHIP_MCP_OPEN
AuthUserFile （そのまま）
AuthName （そのまま）
AuthType Basic
<RequireAny>
Require env SHIP_MCP_OPEN
Require env REDIRECT_SHIP_MCP_OPEN
Require valid-user
</RequireAny>
```

- `REDIRECT_SHIP_MCP_OPEN` は、WordPress の書き換え（index.php）の後でも通すために要る。
- サーバーの管理画面で Basic 認証を設定し直すと、この形が元に戻ることがある（戻ると、ブラウザで許可する接続だけが使えなくなる）。
- デモサイトに入れておけば、コピーしたサイトにも引き継がれる。

## 3-2. トークンを発行して指示者に渡す（招待コードが使えないとき）

1. 「設定 → Ship Content MCP → 接続」の「トークンを発行する」で、ユーザー（ふつうは「MCP 用のユーザーを新しく作る」）・名前・入口の URL・Basic 認証（公開前のサイトだけ）を入れて発行する。
2. 出てきた「AI に貼る文」を、指示者に DM で送る（指示者は自分の AI に貼るだけ。AI が自分で MCP の設定に登録する）。Claude デスクトップアプリ（チャット）を使う指示者には、「拡張機能をダウンロード」のファイルとトークンを送る（ファイルにトークンは入っていない）。AI に頼まず自分で設定したい人向けのコマンドは「自分で設定するとき」にある。トークンはこの1回だけ表示される。
3. 漏れた・担当が替わったときは、「発行したトークン・鍵」の一覧で「止める」。

- **デモサイトで発行しておけば、デモサイトからコピーしたサイトでも同じトークンが使える**（トークンのハッシュとユーザーが DB ごとコピーされるため）。指示者はコマンドの入口の URL だけ変えればよい。止めるときは、コピーした各サイトで止める（`wp ship-content-mcp keys revoke --key-id=<鍵 ID>`）。
- トークンは HTTP でも受け付ける（基本設定の「トークンを HTTP でも受け付ける」。公開前の確認用 URL のため）。HTTP ではトークンが暗号化されずに流れるので、**公開するときはプラグインごと外す**（下の「公開の前に片付ける」）。
- WP-CLI でも発行できる：`echo -n 'ID:パスワード' | wp ship-content-mcp keys token --for-user=new --label=制作チーム --basic-auth-stdin`（`--for-user` は既存のユーザー ID でもよい。入口を変えるときは `--entry-url=`）。
- 写真は、AI が `get-upload-url` でもらった URL（30分・1回だけ）に curl で送る。サーバーの Basic 認証があるサイトでは、MCP の接続で届いた Basic 認証を、そのコマンドに入れて返す。

### 公開の前に片付ける

1. 「接続」タブの「すべて止めて、MCP を止める」を押す（または `wp ship-content-mcp prelaunch --yes`）。発行した招待コード・接続・トークン・鍵がすべて止まり、MCP の入口がなくなる。
2. 「プラグイン」で「Ship Content MCP」と「MCP Adapter」を無効にして削除する（または `wp plugin delete ship-content-mcp mcp-adapter --deactivate`）。このプラグインの表・設定・制作方針・記録・ロールも消える（`uninstall.php`）。作った下書き・写真と、MCP 用のユーザーは残る。
3. REST を止めるコード（Snippet など）に足した `ship-content/` の例外も、要らなければ外す。Basic 認証の例外（上の `SHIP_MCP_OPEN`）は、公開で Basic 認証ごと外すなら一緒に消える。

### ほかのつなぎ方

「接続」タブの「ほかのつなぎ方」に、接続コード（中継プログラムの setup 用）と、端末の公開鍵の登録（keygen。秘密が指示者のパソコンから出ない、いちばん堅い方式）がある。ふだんは使わない。

## 4. 制作方針の書き方

- 「サイト共通」と「投稿タイプ別」に、自然な文章で書く。入力欄の field key は書かなくてよい（構造が変わっても書き直さなくてよい）。
- AI は、方針と入力欄の選択肢（表示名）を照らして値を選ぶ。表示名と同じ言葉で書くと伝わりやすい（例：「施工後の写真は基本 PC 2カラム」）。
- 実際の AI での試験から、次も書いておくとよい：
  - アイキャッチにする写真（例：「アイキャッチは施工後の1枚目」）
  - 分類の選び方（例：「施工事例カテゴリは施工箇所から選ぶ」）。合う語がないとき、AI は語を足せる（基本設定の「AI が分類の語を足せる」。見出しの親も足せる・同じ語は作らない・似た語は指示者に確かめる）。足す語の書き方（例：「エリアは市町村名で。スラッグはローマ字」）も書いておくとよい。足した語は基本設定の「AI が足した語」に出る
  - コンセプト（見出し・説明）の書き方と、材料がないときの扱い（例：「指示者の依頼にないときは、施工内容から短くまとめる」または「空のままにする」）
  - 書いてはいけないこと（費用・工期の推測、お客様の名前・番地など）
- 「AI が読む内容の確認」で、AI に渡る文を確かめられる。変えると版が上がり、履歴に残る。

## 5. 写真

- JPEG・PNG・WebP だけ。上限は基本設定で変えられる（初期 20MB）。
- 位置情報などのメタデータは、初期設定で消える（向きは写真に反映してから消す）。
- **メディアの写真は、記事が下書きでも URL を知っていれば見られる。** 公開してよい写真だけを登録する運用にする。

## 6. 記録・片付け・止め方

- 「記録」：接続の拒否・ツールの実行・認証の失敗・管理の操作（本文・画像・パスワードは記録しない。90日で消える）。
- 試験の片付け：`wp ship-content-mcp cleanup-tests`（一覧）→ `--yes`（消す）。
- すぐ止める：基本設定で「MCP を受け付ける」を外す（または `wp ship-content-mcp disable`）。入口がなくなる。

## 7. WP-CLI

| コマンド | すること |
|---|---|
| `wp ship-content-mcp status` | 診断（対処つき） |
| `wp ship-content-mcp selftest` | 自己テスト（読み取り中心） |
| `wp ship-content-mcp enable` / `disable` | MCP を受け付ける・止める |
| `wp ship-content-mcp post-type <name> <off\|unverified\|testing\|tested\|active> [--reverify]` | 投稿タイプの使い方（試験合格・稼働で構造を記録） |
| `wp ship-content-mcp keys list\|token\|issue\|add\|revoke` | トークン・接続コード・端末の鍵 |
| `wp ship-content-mcp prelaunch [--yes]` | 公開の前の片付け（すべて止めて、MCP を止める） |
| `wp ship-content-mcp cleanup-tests [--yes]` | 試験の下書き・写真・転送の片付け |
