# PM 向けの手順（AI エージェントから下書きを作る）

このプラグインを入れたサイトに、手元の AI エージェント（Claude Code・Claude Desktop など、MCP に対応したもの）からつないで、施工事例などの**下書き**を作ります。公開は、人が WordPress の管理画面で行います（AI からは公開・削除はできません）。

## 0. ブラウザで許可してつなぐ（おすすめ）

管理者から2つ届きます：**① AI に貼る文**（秘密は入っていません）と、**② 招待コード**（`XXXX-XXXX-XXXX-XXXX-XXXX`）。

1. ① を自分の AI（Claude Code・Codex など）にそのまま貼って送ります。AI が自分の MCP の設定に登録します（「実行してよいか」と聞かれたら「許可」）。
2. ログイン（認証）を始めると、ブラウザに「AI からの接続を許可しますか？」の画面が出ます。② の招待コードを入れて「許可する」を押します。
   - Claude Code：AI からはログインを始められません。Claude Code を開き直して `/mcp` と打ち、登録したサーバーを選んで「Authenticate（認証）」を押します（`/mcp` が使えないときは、ターミナルで `claude mcp login <名前>`）。
   - Codex：登録するとすぐにブラウザが開きます（開かなければ `codex mcp login <名前>`）。
   - ほかのアプリ：アプリの MCP の画面で「接続」「認証」などを押します。
   - サーバーの Basic 認証があるサイトでは、ブラウザが ID とパスワードを聞きます（サイトの確認に使っているもの）。
3. 「AI の画面に戻ってください」と出たら終わりです。AI に「（サイト名）で使える投稿タイプを教えて」と聞き、投稿タイプが返ってくれば使えます。

- うまくつながらないときは、AI が原因を見分けます。**管理者が直すものだけ**、AI が「管理者に送る文」を作るので、それをコピーして管理者に送ります。自分で直せるもの（写し間違い・アプリの開き直しなど）は、AI が直し方を教えます。
- **招待コードは AI に貼らないでください**（ブラウザの画面にだけ入れます）。1回だけ使えます。期限（初期 7日）が切れたら、管理者に新しいものをもらいます。
- 許可は初期 90日で切れます。切れたら、管理者に新しい招待コードをもらって、2. をやり直します。ふだんは AI が自動でつなぎ直すので、何もしなくてかまいません。
- **自分で AI に頼んで開いた画面のときだけ**許可します。人から送られてきたリンクで開いた画面では許可しないでください。
- パソコンを替えたときは、新しいパソコン用に招待コードをもらいます（1台に1つ）。
- 写真：AI がツール `get-upload-url` でアップロード用の URL をもらい、`curl` で写真を送ります（コマンドを実行できる AI なら、頼むだけで自動で行います）。
- この仕組みは、公開前（制作中）のサイトで使う前提です。公開したサイトでは、管理者がプラグインごと外します。

### 0-2. トークンでつなぐ（招待コードが使えないとき）

管理者がトークンを発行すると「AI に貼る文」が届きます。自分の AI にそのまま貼るだけです。文にはトークンが入っているので、AI との会話に入ります（AI の会社のサーバーを通ります）。トークンは合鍵と同じです。人に渡したり、共有のチャンネルに貼ったりしないでください。漏れたら管理者に止めてもらいます。デモサイトからコピーしたサイトでは、同じトークンが使えます（入口の URL だけ変える）。

## A. 接続コードで設定する（ほかのつなぎ方。ふだんは使いません）

管理者から「接続コード」（`shipmcp1.` で始まる文字列）が届きます。使う AI によって、設定の仕方が3通りあります。どれも、この 0. で設定したときは、下の 1.〜4. は要りません。

| 使う AI | 設定の仕方 | 確かめたこと |
|---|---|---|
| Claude デスクトップアプリ（チャット） | 拡張機能のファイルを開いて、接続コードを貼る（0-1） | 拡張機能の形式（公式の検査道具）と、中身の動き |
| Claude Code（デスクトップアプリの「Code」・ターミナル） | 決まった文を貼る（0-2） | 本物の AI で、Node.js なしから設定・接続まで |
| ほかの AI（Cursor・VS Code・Gemini CLI・Codex CLI など、手元の MCP サーバーを使えるもの） | 決まった文を貼るか、表示された設定を貼る（0-3） | 未確認 |

ブラウザだけで使う AI（ChatGPT のウェブ版など、手元のプログラムを動かせないもの）では使えません。

接続コードは合鍵と同じです。人に渡さず、AI の会話にも貼りません（0-1 は拡張機能の設定の欄に、0-2・0-3 は中継プログラムがクリップボードから直接読みます）。

### A-1. Claude デスクトップアプリ（チャット）

1. 管理者から届いた拡張機能のファイル（`ship-content-<名前>.mcpb`）を開く（ダブルクリック）。Claude デスクトップアプリに、拡張機能を入れる画面が出ます。
2. 画面の案内に沿って入れる（署名のない拡張機能という注意が出たら、管理者から届いたファイルであることを確かめて進めます）。
3. 「接続コード」の欄に、管理者から届いた接続コードを貼って保存し、拡張機能を有効にする（メッセージを丸ごと貼ってもかまいません）。
4. 新しいチャットで「（サイト名）で使える投稿タイプを教えて」と聞く。

Node.js などを入れる必要はありません（Claude デスクトップアプリに入っています）。サイトごとに拡張機能が分かれているので、別のサイトも使うときは、そのサイトの拡張機能と接続コードで同じことをします。

### A-2. Claude Code（デスクトップアプリの「Code」・ターミナル）

次の文を Claude Code に貼ります。Node.js を入れる・中継プログラムを置く・設定のファイルを作る・Claude Code に登録する、はすべて AI と中継プログラムが行います。

- AI が「このコマンドを実行してよいか」と聞いてきたら、「許可」を押します。
- 「接続コードをコピーしてください」と言われたら、管理者からのメッセージをコピーして「コピーした」と返します。

```text
管理者から届いた「接続コード」で、記事の下書きを AI で作る仕組み（Ship Content MCP）を、このパソコンで使えるようにしてください。
私はパソコンに詳しくありません。作業はすべてあなたが行い、私には結果だけを短く教えてください。
接続コードは秘密です。あなたは中身を読んだり表示したりせず、中継プログラムにクリップボードから直接読ませてください。

1. Node.js（18 以上）が使えるか確かめる。なければ、管理者のパスワードが要らない方法で入れる：nodejs.org の公式の配布物（LTS・このパソコンに合うもの）を、同じ場所の SHASUMS256.txt で照合してから、~/.ship-content-mcp/node に展開する。
2. 中継プログラムを次からダウンロードし、同じ場所の ship-content-mcp-bridge.mjs.sha256 で照合してから、~/.ship-content-mcp/ship-content-mcp-bridge.mjs に置く（すでにあれば置き換える）：
   https://github.com/ship-git-admin/ship-content-mcp/releases/latest/download/ship-content-mcp-bridge.mjs
3. ここまでできたら、私に「管理者から届いた接続コードをコピーしてください」と伝える。私が「コピーした」と答えたら、1. の node で「~/.ship-content-mcp/ship-content-mcp-bridge.mjs setup --clipboard --register」を実行する（接続の確認と、Claude への登録まで行われる）。
4. 結果を短く教えて。うまくいかないときは、出たメッセージを、私が管理者にそのまま送れる形でまとめる。
```

設定が済んだら、Claude Code で**新しいセッションを開いて**（登録はセッションの始めに読まれます）、「（サイト名）で使える投稿タイプを教えて」と聞きます。投稿タイプが返ってくれば使えます。別のサイトも使うときは、そのサイトの接続コードで同じ文を貼ります（サイトごとに別の名前で登録されます）。

### A-3. ほかの AI

コマンドを実行できる AI（エージェント）なら、次の文を貼ります。0-2 との違いは、最後に AI 自身の MCP の設定へ登録するところです。

```text
管理者から届いた「接続コード」で、記事の下書きを AI で作る仕組み（Ship Content MCP）を、このパソコンで使えるようにしてください。
私はパソコンに詳しくありません。作業はすべてあなたが行い、私には結果だけを短く教えてください。
接続コードは秘密です。あなたは中身を読んだり表示したりせず、中継プログラムにクリップボードから直接読ませてください。

1. Node.js（18 以上）が使えるか確かめる。なければ、管理者のパスワードが要らない方法で入れる：nodejs.org の公式の配布物（LTS・このパソコンに合うもの）を、同じ場所の SHASUMS256.txt で照合してから、~/.ship-content-mcp/node に展開する。
2. 中継プログラムを次からダウンロードし、同じ場所の ship-content-mcp-bridge.mjs.sha256 で照合してから、~/.ship-content-mcp/ship-content-mcp-bridge.mjs に置く（すでにあれば置き換える）：
   https://github.com/ship-git-admin/ship-content-mcp/releases/latest/download/ship-content-mcp-bridge.mjs
3. ここまでできたら、私に「管理者から届いた接続コードをコピーしてください」と伝える。私が「コピーした」と答えたら、1. の node で「~/.ship-content-mcp/ship-content-mcp-bridge.mjs setup --clipboard --print-config」を実行する（接続の確認まで行われ、AI に登録する設定が表示される）。表示された設定を、あなた（このアプリ）の MCP の設定に登録する。登録の場所が分からなければ、その設定を私に示し、どこに貼ればよいかを教える。
4. 結果を短く教えて。うまくいかないときは、出たメッセージを、私が管理者にそのまま送れる形でまとめる。
```

AI がコマンドを実行できないときは、0-2 の 1.〜2. と同じ準備をしてから、ターミナルで `node ~/.ship-content-mcp/ship-content-mcp-bridge.mjs setup --clipboard --print-config` を実行し、表示された設定（`mcpServers` の形）を、その AI の MCP の設定に貼ります。

## 1. 用意するもの（手で設定する場合）

接続コードがあるときは、中継プログラムを置いて `node ship-content-mcp-bridge.mjs setup --clipboard --register` を実行するだけで足ります（コードをクリップボードにコピーしてから）。以下は、鍵を自分のパソコンで作る方式（keygen）です。


- Node.js 18 以上
- 中継プログラム `ship-content-mcp-bridge.mjs`（このリポジトリの `bridge/`）。例：`~/ship-content-mcp/` に置く
- サイトの管理者に作ってもらう、自分用のユーザー（権限グループ「Content MCP Operator」）

## 2. 鍵を作る（端末ごとに1回）

```bash
node ~/ship-content-mcp/ship-content-mcp-bridge.mjs keygen --out ~/.ship-content-mcp/example.key
```

- 表示された「公開鍵」を、サイトの管理者に送ります（公開鍵は秘密ではありません）。
- **秘密鍵のファイル（`.key`）は人に渡さないでください。** パソコンを替えたときは、新しく鍵を作ります。
- 管理者が登録すると、次の3つを受け取ります：MCP の入口（URL）・鍵 ID・サイトの公開鍵。

## 3. つながるか試す

```bash
SHIP_MCP_URL=（MCP の入口） SHIP_MCP_KEY_ID=（鍵 ID） SHIP_MCP_KEY_FILE=~/.ship-content-mcp/example.key SHIP_MCP_SERVER_KEY=（サイトの公開鍵） node ~/ship-content-mcp/ship-content-mcp-bridge.mjs check
```

「接続できました」と、ツールの一覧が出れば OK です。サーバーの Basic 認証があるサイト（公開前の確認用 URL など）は、`SHIP_MCP_BASIC_AUTH=ID:パスワード` も付けます。

## 4. AI エージェントに登録する

**Claude Desktop**：設定ファイル（`claude_desktop_config.json`）に、`bridge/mcp-config.example.json` と同じ形で書きます。

**Claude Code**：

```bash
claude mcp add ship-content-example --scope user -e SHIP_MCP_URL=… -e SHIP_MCP_KEY_ID=… -e SHIP_MCP_KEY_FILE=… -e SHIP_MCP_SERVER_KEY=… -e SHIP_MCP_UPLOAD_DIRS=… -- node ~/ship-content-mcp/ship-content-mcp-bridge.mjs
```

- `SHIP_MCP_UPLOAD_DIRS`：写真を送ってよいフォルダ（区切りは `:`）。指定しなければホームフォルダ。隠しフォルダの中は送れません。
- サイトごとに名前を変えて登録します（例：`ship-content-サイト名`）。

## 5. 頼み方（例）

> サイト「○○」に、施工事例の下書きを作ってください。
> - 地域：○○市（番地は書かない）／建物：木造2階建て／施工箇所：外壁・屋根
> - 内容：（現場で行ったこと）
> - お客様のご要望：（聞いた内容）／ご提案：（提案した内容）
> - 費用・工期：（書いてよければ）
> - 写真：~/Pictures/現場A/ の before_*.jpg が施工前、after_*.jpg が施工後
>
> 制作方針と入力欄を読んでから、方針に沿って作ってください。保存の前に validate-draft で確かめ、作ったら post_id と、どの欄に何を入れたかを教えてください。

- AI は、サイトの**制作方針**（管理者が書いたもの）と、そのときの**入力欄の構造**を毎回読んでから作ります。
- 事実（費用・工期・製品名・お客様名）は、渡したものだけを使うよう方針に書いてあります。足りないと AI が聞いてきます。
- 直したいときは「下書き ○○ のご提案を、こう直して」と頼みます。既存の内容を消す変更は、AI があなたに確かめてから行います。

## 6. 写真について

- JPEG・PNG・WebP だけ送れます。**iPhone の HEIC は、JPEG に変換してから**送ってください。
- 撮影場所（GPS）などの情報は、サイトに登録するときに消えます。
- **メディアに登録した写真は、記事が下書きのままでも、URL を知っていれば誰でも見られます。** 公開してよい写真だけを送ってください（お客様の顔・表札・車のナンバーなどに注意）。

## 7. 下書きの確認と公開

AI が作った下書きは、WordPress の管理画面で確認します（プレビュー・編集）。直したら、人が「公開」します。

## 8. 困ったとき

| AI に出る内容 | 意味 | どうする |
|---|---|---|
| サイトにつながりません／時間切れ | ネットワーク・URL の誤り | URL とネットワークを確かめる |
| 許可の画面で「招待コードが違います／使用済み／期限が切れています」 | 招待コードの写し間違い・使ったもの・期限切れ | そのまま貼り直す。直らなければ管理者に新しい招待コードをもらう |
| 許可の画面で「戻り先が登録と違います」「AI の登録が見つかりません」 | AI の登録が古い | AI の画面から、もう一度ログイン（認証）を始める |
| Needs authentication（認証が要る）・接続の期限が切れた | 許可が切れた・止められた | 管理者に新しい招待コードをもらい、ログインし直す |
| Basic 認証で止まった（HTTP 401、署名なし） | サイトの入口の認証 | `SHIP_MCP_BASIC_AUTH` を確かめる |
| MCP の入口が見つかりません（404） | MCP が止まっている・URL 違い | 管理者に確認 |
| 返事の署名が合いません | サイトの公開鍵の設定違い（または通信の途中の書き換え） | `SHIP_MCP_SERVER_KEY` を確かめる。直らなければ管理者に連絡 |
| MCP-002 認証に失敗しました | 鍵が止められた・鍵 ID 違い・パソコンの時計のずれ | 時計を合わせる。直らなければ管理者に連絡 |
| AUTH-001 この操作は許可されていません | ユーザーの権限・接続元の制限 | 管理者に確認 |
| MCP-003 この投稿タイプは利用できません | 管理者が許可していない投稿タイプ | 管理者に確認 |
| WRITE-001 まだ書き込みが許可されていません | 投稿タイプが「未検証」 | 管理者に確認 |
| ACF-001 入力構造が変わりました | 読んだ後に入力欄が変わった | AI に「構造を読み直して」と頼む |
| ACF-003 管理者が確かめた後に変わりました | 入力欄の変更を、管理者がまだ確かめていない | 管理者に確認 |
| CONFLICT-001 他の編集があった・編集中 | 人が管理画面で編集中、または読んだ後に変わった | 編集が終わってから、AI に読み直して直してもらう |
| EDIT-001 既存の内容を消す変更 | 行を減らす・空にする変更 | 消してよいか確かめて、AI に伝える |
| MEDIA-001・MEDIA-002 写真 | 写真の形式・大きさ・転送の失敗 | JPEG などに変換・小さくして、もう一度 |

## 9. パソコンをなくした・担当が替わった

すぐに管理者へ連絡し、その接続（または鍵・トークン）を止めてもらいます（管理画面「接続」→ 一覧の「止める」）。ほかの人の接続は影響を受けません。
