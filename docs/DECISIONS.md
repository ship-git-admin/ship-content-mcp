# 決定の記録

| ID | 決めたこと | 理由 |
|---|---|---|
| D-001 | プラグインのスラッグは `ship-content-mcp`、Ability の名前空間・MCP のサーバー ID は `ship-content`。入口は `/wp-json/ship-content/mcp` | 社内標準の名前。ツール名は公式 Adapter の決まりで `ship-content-list-post-types` のようになる |
| D-002 | 認証は「端末の署名（Ed25519）」と「Application Password」の2つ。署名は `Authorization` を使わず、応答にもサイトの鍵で署名する | HTTP の動作確認URL・サーバーの Basic 認証のあるサイトでも、パスワードを通信に乗せずに使うため（docs/AUTH_SIGNATURE.md） |
| D-003 | ツール（Ability）は `meta.public`・`show_in_rest` を付けず、`meta.mcp.public=false`。自作サーバーの一覧にだけ書く | 公式 Adapter 0.7.2 は、自作サーバーの一覧に書いた Ability を公開の印なしで載せる（ソースで確認）。WordPress 7.1 は `meta.public` を REST の公開にも使う。既定サーバーにもコアの REST にも出さない |
| D-004 | 公式の既定サーバーは、初期設定で止める | 既定サーバーは、公開の印の付いたほかの Ability（コアのものを含む）を、`read` を持つ人に出す |
| D-005 | 入れた直後は MCP を受け付けない（管理者が有効にする） | 入れただけで入口が開かないようにする |
| D-006 | 投稿の編集・公開・アップロード・設定変更などの権限を持つユーザーは、MCP で使えない（初期設定） | 同じ認証で標準の REST から記事を書き換えられないようにする。PM には `read` と専用の権限だけのロールを使う |
| D-007 | ツールは、REST の振り分けが MCP の入口のとき（または WP-CLI）だけ動く。権限は接続のとき・ツールごと・処理の中の3回確かめる | ほかの経路（コアの REST、既定サーバーなど）から呼ばれても動かないようにする |
| D-008 | 新しい下書きの ACF の構造は「ID なしの仮の投稿（post_id=0）＋予定の分類」で判定し、推定として返す | ACF は投稿 ID がないと分類の条件を「一致なし」と判断し、`post_taxonomy != …` のグループまで外してしまう（ACF のソースで確認）。保存の前には実際の下書きで判定し直す（F2） |
| D-009 | `schema_fingerprint` は、ラベル・説明文・選択肢の表示名を含めない | 表示の言い換えでは、保存を止めないため。key・型・選択肢の値・入れ子・location が変われば変わる |
| D-010 | 失敗は、公式 Adapter のエラーの印（isError）付きの文章として返し、その文章に `{ok:false, error:{code, message, admin_detail, retryable, who_fixes, next_step}, request_id}` の JSON を入れる（who_fixes・next_step は 0.9.1 から） | Adapter は WP_Error の文だけを AI に返すため。admin_detail には IP・鍵・パスワードを入れない |
| D-011 | WP-Cron に頼らない（使い捨て番号・記録の片付けは、リクエストのついでに行う） | Basic 認証のあるサイトでは WP-Cron が動かないことがある |
| D-012 | 制作方針の出力は `contracts/policy_output.schema.json` の形にし、更新日時などは `meta` に入れる。版は「保存して変わった回数 + 1」 | 契約の Schema は追加の項目を許さないため |
| D-013 | 固定ページ・メディア・ACF の定義・内部の投稿タイプ（公開でないもの）は、設定にかかわらず使わせない | サイトの構造や、コードを作る投稿タイプ（JS/SCSS など）を AI から変えさせない |
| D-014 | 接続元の IP 制限は任意（初期は制限なし）。使うときは REMOTE_ADDR だけを見る | PM の接続元は変わりやすい。署名・端末ごとの停止・低権限で守る。X-Forwarded-For は偽れるので見ない |
| D-015 | 投稿タイプの状態に「試験中」を足す。書けるのは「試験中・試験合格・稼働」だけ。試験中に作った下書きには試験の印を付け、`wp ship-content-mcp cleanup-tests --yes` で片付ける | 実機で書き込みを試してから「試験合格」にするため。未検証の構造には書かない |
| D-016 | ACF の値は、上の階層も入れ子も field key で指定する。flexible content の行は `acf_fc_layout` にレイアウトの name。get-post は ACF の「保存されたままの形」（同じ形）で返す | name は重なることがある。読んだ形のまま直して送り返せるようにする |
| D-017 | 作成は「推定の構造で確かめる → 印付きの下書きを作る → 実際の下書きで判定し直す → 書く → 読み戻す」。推定と違えば、作った下書きを消して ACF-001 | ACF は投稿 ID がないと location を正しく判定できない（D-008）。スタブは非公開の下書きで、失敗したら自分で消す |
| D-018 | 修正は、上の階層の欄ごとの置き換え（指定しなかった欄・投稿の項目は変えない）。既存の値を空にする・行を減らす・選んだものを外す・分類を外す・flexible の行のレイアウトを変える変更は、`allow_removals=true` がないと止める（EDIT-001）。契約 `draft_patch` に `schema_fingerprint`・`allow_removals` を足す | ACF に慣れない AI が、大きな配列を誤って上書きして消すのを防ぐ。入れ子で書かなかった欄は ACF が前の値を残すので、消す変更に数えない |
| D-019 | 版の印（if_match）は、題名・本文・状態・分類・アイキャッチに加えて ACF の値から作る。管理画面で人が編集中（編集ロック）のときは書かない | ACF の値だけが変わっても更新日時は動かないため。人の編集とぶつけない |
| D-020 | 修正の前の値を投稿の meta（`_ship_content_mcp_snapshots`、新しい順に5件）に控える。途中で失敗したら控えから戻す。書いている間に公開に変わっていたら戻さない（記録だけ） | WordPress と ACF の保存は1つのトランザクションにならないため、補償で戻す。公開済みの記事は書き換えない |
| D-021 | 二重送信の防止は専用の表（ユーザー・キーごと）。同じ内容なら前の結果、違う内容なら拒否（IDEM-001）、処理中なら拒否（IDEM-002）、失敗したら解放 | 通信の送り直しで下書きが2つできないように。同時に来ても主キーで1回だけ通す |
| D-022 | 文字列（text・textarea）は HTML を含むときだけ `wp_kses_post`、wysiwyg は常に。本文（post_content）は WordPress の標準（PM のユーザーには unfiltered_html がないので kses が効く） | スクリプトなどを消す。「&」などの普通の文字を書き換えない |
| D-023 | 関連する記事は公開済み・欄が許す投稿タイプだけ。画像は既存の画像の添付 ID（写真の転送は F3） | ACF 6.8.11 も、読めない投稿を関連に保存しない。URL からの取得はしない（SSRF を防ぐ） |
| D-024 | 必須の欄が空でも下書きは保存し、警告（missing_required）で返す | 下書きは途中の状態を許す。公開は人が管理画面で行う |
| D-025 | ACF の値を書いた後に `acf_save_post_revision`（ACF の公式の関数）で最新のリビジョンへ写す | ACF はプレビューのとき値を最新のリビジョンから読む。update_field で書いた値は写らず、題名などの修正でリビジョンができるとプレビューが空になる（実機で確認） |
| D-026 | text・textarea・wysiwyg の `script`・`style` は、中身ごと消してから wp_kses_post を通す | wp_kses_post はタグだけを消し、中の文字（`alert(1)` など）を本文に残すため（実機で確認） |
| D-027 | 写真は、中継プログラムのローカルのツール `ship-content-upload-local-image` で送る（AI はパスを渡すだけ）。サーバーのツール（prepare-upload・upload-chunk・finish-upload）はキットどおりに用意し、中継プログラムがそれを呼ぶ | AI に写真の base64 を作らせるのは現実的でない（1枚で数十万トークン）。分割・ハッシュ・送り直しは中継プログラムが確実に行う |
| D-028 | ローカルのツールで送れるのは、許されたフォルダ（`SHIP_MCP_UPLOAD_DIRS`、既定はホーム）の中で、隠しフォルダ・隠しファイルでなく、先頭の印と拡張子が一致する JPEG・PNG・WebP だけ（100MB まで）。拒否したときはサーバーに何も送らない | 書き込まれた指示などで、AI が鍵や設定などの別のファイルを送らされるのを防ぐ |
| D-029 | 分割の途中は DB に base64 のまま置く（公開の場所に置かない）。仕上げで一時ファイルに組み立て、確かめてから WordPress のメディアへ移す | サーバーの公開フォルダに途中のファイルを置かないため。wpdb は不正な UTF-8 を含む問い合わせを落とすことがあるので、バイナリではなく base64 にする |
| D-030 | 写真の位置情報（GPS）などのメタデータを、登録の前に消す（初期は有効）。向き（Orientation）を写真に反映してから消し、色の情報（ICC）は残す。消した後にもう一度確かめ、残っていれば登録しない | 施工写真の撮影場所から、お客様の住所が分かってしまうのを防ぐ。WordPress は元の写真の EXIF を残すため |
| D-031 | 受け付けるのは JPEG・PNG・WebP だけ。拡張子・申告の MIME・先頭の印・getimagesize・finfo がすべて一致すること。大きさは設定の上限（1〜100MB、初期 20MB）、縦横 15,000px・6,000 万画素まで。URL からの取得はしない | MIME の偽装・SVG のスクリプト・巨大な画像によるメモリ不足・SSRF を防ぐ |
| D-032 | 同じ写真（ファイル全体の SHA-256 が同じ）が MCP で登録済みなら、転送せずにその添付 ID を返す | やり直しで同じ写真が何枚も登録されるのを防ぐ |
| D-033 | 分割：同じ番号に同じ中身は受け付ける（送り直し）、違う中身は拒否。仕上げた後の分割は拒否。転送は2時間で期限切れ、1人の転送中は10件まで。ほかのユーザーの転送は「ない」と同じに扱う | 通信の送り直しに強くしつつ、すり替えや溜め込みを防ぐ |
| D-034 | メディアの写真は、記事が下書きでも URL を知っていれば見られる。このことを管理画面・ツールの説明・返事に明記する。非公開のメディアの仕組みは作らない | WordPress の仕組み。公開してよい写真だけを登録する運用にする |
| D-035 | upload-chunk の成功は記録しない（失敗は記録する） | 1枚で数十行になり、記録が読めなくなるため |
| D-036 | 状態を「試験合格」「稼働」にしたとき（または「確かめ直した」とき）に、その投稿タイプで使われうる ACF のグループの指紋を記録する。分類で切り替わるグループ（location の post_taxonomy の条件）も含める。その後に構造が変わったら、確かめ直すまで書き込みを止める（ACF-003）。「試験中」は止めない | キットの「未検証の構造には書かない」。ACF の変更が AI の書き込みに黙って影響しないよう、管理者の確認を挟む。指紋はラベル・説明文を含めないので、言い換えでは止めない |
| D-037 | 診断の各項目に「対処」を出す。診断は管理者だけが見る。PM には、エラーのコードと短い説明だけを返す | キットの「理由・対処を提示し、一般 PM にはサーバー詳細を隠す」 |
| D-038 | ほかの投稿タイプ（ブログなど）は、管理者が「使う」にして未検証 → 試験中 → 試験合格の順に進める。最初から全部を使えるようにはしない | キットの F4。投稿タイプごとに入力欄・表示が違うため |
| D-039 | WP-CLI に `post-type <name> <status>` を足す（管理画面の基本設定と同じ。試験合格・稼働で構造を記録） | ブラウザなしで、ステージングの試験や複数サイトの設定ができるように |
| D-040 | 本文（post_content）の `script`・`style` も中身ごと消してから保存する（残りは WordPress の kses） | WordPress の kses はタグだけを消し、中の文字を本文に残すため（実機のブログで確認） |
| D-041 | 写真の登録の返事に URL（元・large）を入れる（登録済みの写真を返すときも） | 本文に写真を入れる投稿タイプ（ブログなど）で、img に使うため。メディアの URL は公開されている（D-034） |
| D-042 | 更新は、同梱の Plugin Update Checker v5.7 で GitHub の「公開済みの最新リリース」に添付した `ship-content-mcp-X.Y.Z.zip` だけを使う（ブランチ・タグへの切り替えは止める）。トークンは使わない。止める定数・取得元を変える定数を用意する | 自社のほかのプラグインと同じ版（v5p7）。タグの push・下書きのリリースの段階では各サイトに届かず、人が公開して初めて届く |
| D-043 | 配布用 ZIP は道具（tools/build_release.py）で作る。同じ入力から同じ ZIP、`.md` を含めない、版の一致・同梱ライブラリの指紋（vendor.lock.json）・秘密・PHP の構文を検査し、manifest と SHA-256 を出す。中継プログラムも版を確かめてリリースに添付する | 公開する前に、混入と版の食い違いを機械的に止める。サーバーに `.md` を置かない決まりにも合う |
| D-044 | タグを push すると、CI が検査してから「下書き」のリリースを作る。公開（Publish）は人が確認してから | 誤って各サイトに配らないため |
| D-045 | 端末の鍵を「接続コード」でも渡せるようにする（0.6.0）。管理者がサーバーで鍵の組を作って公開鍵だけを登録し、種と接続の値（入口・鍵 ID・サイトの公開鍵・任意で Basic 認証）を1本の文字列にして1回だけ表示する。PM は `setup --clipboard --register` で設定する。keygen の方式も残す | PM の手間（鍵づくり・公開鍵の往復・値の書き写し）をなくすため。キットの想定（管理者が端末ごとに発行して渡す）と同じ形で、通信に秘密を乗せない署名方式は保つ。引き換えに秘密が管理者・DM を通るので、合鍵として扱い、漏れたら止める |
| D-046 | Claude デスクトップアプリ（チャット）向けに、拡張機能（MCPB）を管理画面からサイトごとに作ってダウンロードさせる（0.7.0）。中身は manifest と同梱の中継プログラムだけで、接続コードは拡張機能の設定の欄（sensitive）に貼る。名前をサイトごとにし、サイトの公開鍵を入れて別のサイトのコードを止める | PM が Node.js もターミナルも使わずに済むため。1つの拡張機能に複数のサイトをまとめると中継が複雑になるので、サイトごとに分ける。秘密をファイルに入れないので、ファイルは同じサイトの PM で共有できる |
| D-047 | トークン方式を足して、これをいちばんの方法にする（0.8.0）。管理画面で発行し、AI の MCP の設定に `X-Ship-MCP-Token` ヘッダーで入れるだけ。サイトには SHA-256 だけを置く。HTTP でも受け付ける（設定で切れる）。写真は1回だけ使える URL に curl で送る。公開時は「すべて止める」＋プラグインの削除（uninstall でデータも消す） | ユーザーの方針「とにかくシンプルに。公開時に MCP を削除するフローで安全を担保」（2026-11-24）。公開前（制作中）だけ使うので、HTTP の確認用 URL でも直接つなぐ。デモサイトで発行すれば、コピーしたサイトでも同じトークンが使える。Authorization ではなく専用のヘッダーにして、サーバーの Basic 認証とぶつからないようにする。署名方式・接続コードは「ほかのつなぎ方」として残す |
| D-048 | ブラウザで許可する接続（MCP の標準の OAuth 2.1）を足して、おすすめにする（0.9.0）。PM は秘密の入っていない文を AI に貼り、AI が開いたブラウザで管理者の**招待コード**（1回だけ・初期 7日）を入れて許可する。許可は初期 90日、アクセストークン1時間・更新トークンは入れ替え。PKCE は S256 だけ、AI の登録は DCR、戻り先はループバックとアプリ専用の形だけ（https は設定で許したときだけ）。招待・接続は鍵の表の行として持ち、止める・一覧・公開前の片付けを共通にする。Basic 認証のあるサイトは、AI が自動で呼ぶ道だけを Basic 認証の例外にする | ユーザーの方針「トークンが AI の会社のサーバーを通らない」「PM が Mac とは限らない」「コマンドを使わせない、モダンなやり方」（2026-11-24）。招待コードは1回だけ・期限 3か月はユーザーの指定。トークン方式は、ブラウザで許可する接続が使えない AI・サイトのために残す |
| D-049 | つながらないときは、AI が原因を見分けて、管理者が直すものだけを「管理者に送る文」にして PM に渡す（0.9.1）。見分け方は「AI に貼る文」に入れ、ツールの誤りには who_fixes（admin・pm・ai）と next_step を付ける。管理者に送る文に招待コード・トークン・パスワードは入れない | ユーザーの方針「管理者が原因のときだけ内容をコピーして管理者に送るよう案内し、PM の側なら何を直すかを伝える」（2026-11-24）。PM の問い合わせを減らし、管理者に届く内容をそろえる。`.well-known` の状態（200・401 Basic・404）で、サーバーの設定の問題をコマンド1回で見分けられる |
